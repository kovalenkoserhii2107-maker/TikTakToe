# TikTakToe — сетевые крестики-нолики

Красивая браузерная игра «Крестики-нолики» для двух игроков по сети. Работает как статический сайт на GitHub Pages, свой сервер не нужен.

## Возможности

- Главный экран: ввод имени (запоминается в браузере) и список игроков, которые ждут соперника.
- Можно создать свою игру или подключиться к уже созданной.
- Игра по сети в реальном времени.
- Право первого хода переходит к другому игроку каждый раунд.
- Ведётся счёт (победы и ничьи). После раунда показывается, кто победил, затем автоматически начинается следующий.
- Свои ходы каждый игрок видит **крестиками ✕**, ходы соперника — **ноликами ◯**.
- Анимации: прорисовка знаков, линия победы, конфетти, плавные переходы между экранами, анимированный фон.
- **Партию можно прервать и продолжить.** Если кто-то закрыл приложение, потерял связь или вышел в лобби, игра сохраняется. При следующем запуске она открывается сама, с той же доской и тем же счётом. Видно, где сейчас соперник: в игре, в лобби или не в сети.
- Окончательно партия заканчивается только кнопкой «Завершить» (у любого из игроков).

## Установка на телефон (ярлык)

Игру можно поставить на главный экран, и она будет открываться как обычное приложение: на весь экран, без адресной строки.

- **Android (Chrome, Edge, Samsung Internet):** в лобби появляется карточка с кнопкой **«Установить»**.
- **iPhone / iPad:** автоматической установки в iOS нет, поэтому в лобби показана подсказка: нажать «Поделиться», затем «На экран „Домой“».
- Если игра уже запущена с ярлыка, подсказка не показывается. Её можно скрыть крестиком, тогда она не появится 3 дня.

В режиме ярлыка учитываются вырез камеры, «чёлка» и нижняя полоса жестов. Игровое поле подстраивается под высоту экрана. Случайный зум и «оттягивание» страницы отключены.

## Как запустить на GitHub Pages

1. Откройте репозиторий → **Settings → Pages**.
2. В разделе **Build and deployment** выберите **Source: Deploy from a branch**.
3. Укажите ветку (например, `main`) и папку `/ (root)`, нажмите **Save**.
4. Через минуту игра будет доступна по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Откройте ссылку на двух устройствах (или в двух вкладках) и играйте.

## Как это устроено

- `index.html`, `style.css`, `app.js` — сама игра, без сборки и зависимостей.
- `manifest.webmanifest`, `sw.js`, `icons/` — всё для установки ярлыка (PWA). Service worker всегда сначала берёт свежую версию из сети, поэтому после обновления на GitHub Pages у игроков сразу новая версия.
- Сеть: игроки обмениваются сообщениями через публичный MQTT-брокер по WebSocket
  (`wss://broker.emqx.io:8084/mqtt`, запасной — `broker.hivemq.com`).
  Библиотека [MQTT.js](https://github.com/mqttjs/MQTT.js) лежит в `vendor/mqtt.min.js`.
- Присутствие игроков хранится в retained-сообщениях, а при обрыве связи брокер сам удаляет игрока из лобби (Last Will).
- **Каждое устройство — сервер своей копии партии.** Партия хранится на обоих устройствах (localStorage) как история ходов: строка номеров клеток. Доска, счёт, номер раунда и очередь хода каждый раз вычисляются из неё. При каждом ходе и при возвращении игрока устройства обмениваются историей и берут более полную. Ходить может только тот, чья очередь, поэтому одна копия всегда продолжает другую и они не расходятся. Брокер только пересылает сообщения и ничего о партии не хранит.
- У игрока постоянный id (тоже в localStorage), поэтому после перезапуска соперник узнаёт его.
- Свой брокер можно указать параметром: `?broker=wss://host:port/path`.

## Локальный запуск

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```
